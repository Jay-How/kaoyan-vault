### 一、 填空题 (每小题 3 分，共 15 分)

1. 十六进制数 (2B.8)H 转换为八进制数是 ()。 答案： 53.4 解析：
1. 先转二进制： 十六进制的一位对应二进制的四位。 2 → 0010 *B* → 1011 8 → 1000 拼接得到：(00101011.1000)2
2. 再转八进制： 以小数点为界，整数部分向左每三位一组，小数部分向右每三位一组。 整数：010 (2, 补零) | 101 (5) | 011 (3) → 053 小数：100 (4) | 0 (补零) → .4
3. 结果： (53.4)8
2. 计算机的总线按其功能和传输信息的不同, 可分为 ()、()和() 三种。 答案： 数据总线 (Data Bus)、地址总线 (Address Bus)、控制总线 (Control Bus) 解析： 这是计算机组成原理中最基础的系统总线分类。 数据总线： 双向传输，传送数据信息，宽度决定字长。 地址总线： 单向传输，传送地址信息，宽度决定寻址能力。 控制总线： 传送控制信号和时序信号。
3. 数据结构的三要素是数据的 ()、()和()。 答案： 逻辑结构、存储结构 (或物理结构)、数据的运算 解析： 考查严蔚敏《数据结构》第一章核心概念。缺一不可。
4. 线性表若采用链式存储结构, 其优点是便于插入和删除操作, 但其缺点是不能进行 () 存 取。 答案： 随机 (Random) 或 直接 解析： 顺序表（数组）支持 *O*(1) 的随机存取；链表必须从头遍历，只支持顺序存取。

5. 栈 (Stack) 和队列 (Queue) 都是操作受限的线性表。其中, 栈的操作特性是 ()，队列 的操作特性是 ()。

### 二、 判断题 (每小题 3 分，共 15 分)

1. ( F) MIPS (Millions of Instructions Per Second) 是衡量 CPU 性能的唯一标准, MIPS 值越高, 代表计算机的实际运算能力越强。 解析： 错误。MIPS 仅代表每秒执行指令数，但不同架构（RISC vs CISC）的单条指令效能 （CPI）不同。单纯比较 MIPS 不能完全反映实际运行速度。
2. ( F) DMA (Direct Memory Access) 方式在进行数据传输时, 完全不需要 CPU 的干预, 数 据传输过程完全由 DMA 控制器 (DMAC) 控制。 解析： 错误。DMA 在传输开始前（预处理）需要 CPU 初始化，在传输结束后（后处理）需 要 CPU 响应中断进行善后。只有在数据块传输的“过程中”才不需要 CPU 干预。
3. ( T) ARP (Address Resolution Protocol) 协议的功能是已知目标设备的 IP 地址, 查询其 对应的 MAC 地址。
#### 解析： 正确。这是 ARP 的标准定义（网络层与链路层的接口）。

4. ( T) ICMP (Internet Control Message Protocol) 协议是 TCP/IP 协议簇的组成部分, 它 封装在 IP 数据报中传输, 用于报告差错情况和提供网络诊断信息。
#### 解析： 正确。ping 命令就是基于 ICMP 实现的。

5. ( F) 稀疏图 (Sparse Graph) 适合采用邻接矩阵存储, 而稠密图 (Dense Graph) 适合采用 邻接表存储。 解析： 错误。说反了。 稀疏图：边很少，用邻接矩阵会浪费大量 0 空间，适合用邻接表。 稠密图：边很多，用邻接矩阵更紧凑且方便判断边是否存在。
### 三、 选择题 (每小题 3 分，共 21 分)

1. 在参数估计中, 用样本矩来代替相应的总体矩, 从而得到参数估计量的方法称为 ()。
#### 答案： A. 矩估计法

解析： A：利用样本矩（如样本均值）等于总体矩（如期望）建立方程求解。 B：最大似然估计利用似然函数最大化。 D：最小二乘法用于回归分析，使误差平方和最小。

2. 堆排序在最坏情况下的时间复杂度和平均空间复杂度分别是 ( )。 答案： C. *O*(*n*log*n*), *O*(1) 解析： 堆排序是原地排序算法，空间复杂度为 *O*(1)。建堆时间 *O*(*n*)，调整堆时间 *O*(*n*log*n*) ，总时间复杂度稳定在 *O*(*n*log*n*)。
3. 某 C 类网络地址为 192.168.10.0, 现需要将其划分为至少 5 个子网, 则应选用的子网掩码是 ( )。 答案： B. 255.255.255.224 解析：
*k* 3 需要划分 5 个子网，则子网号位数 *k* 需满足 2 ≥ 5。因此 *k* 至少为 3 (2 = 8)。 C 类地址默认掩码 /24。借用 3 位主机号作为子网号，掩码变为 /27。 二进制掩码： 11111111.11111111.11111111.11100000 最后一字节 11100000 转十进制为 128 + 64 + 32 = 224。

4. 在计算机系统总线中, 以下哪种不属于按数据传输方式分类的总线类型 ()。 答案： C. 专用总线 (注：部分教材将D异步归为通信时序，但专用属于功能结构分类，性质 差异最大) 解析： 按传输方式： 分为 串行总线 (Serial) 和 并行总线 (Parallel)。 按时序控制： 分为 同步总线 和 异步总线。 按连接/功能： 分为 专用总线 和 多路复用总线（或系统/IO总线）。 题目问“不属于传输方式”，C（专用）是基于功能连接的，与数据如何“流动”（串行/ 并行）无关，是区别最大的选项。
5. 下列排序算法中, 哪一种是不稳定的排序方法 ( )。 答案： D. 堆排序 (Heap Sort) 解析： 稳定： 冒泡、插入、归并、基数。 不稳定： 快速、希尔、选择、堆排序。 记忆口诀：“快(快排)些(希尔)选(选择)一堆(堆排)心情不稳定”。
6. 在 TCP/IP 协议簇中, 负责在两个应用进程之间提供端到端的、不可靠的数据报服务的协议是 ( )。

答案： C. UDP 协议 解析： IP：网络层，主机到主机。 TCP：传输层，可靠、面向连接。 UDP：传输层，不可靠、无连接、数据报。

7. 计算机中表示带符号整数最常用的编码方式是 ()。 答案： B. 补码 解析： 补码解决了 0 的重码问题（+0 和 -0），并且可以将减法运算转换为加法运算，简化了 ALU 的设计。
### 四、 名词解释 (每小题 6 分，共 24 分)

#### 答题策略： 采用“定义 + 核心特点 + 区别/联系”的结构，体现辨析能力。

1. 树 (Tree) 与 二叉树 (Binary Tree)
(1) 树： 是 *n* (*n* ≥ 0) 个结点的有限集合。在任意一棵非空树中，有且仅有一个根结点，其余 结点可分为 *m* 个互不相交的子集，每个子集又是一棵树。树是一对多的逻辑结构。
(2) 二叉树： 是一种特殊的树形结构，每个结点至多只有两棵子树（度 ≤ 2），且子树有左右 之分，次序不能颠倒。
(3) 区别： 度数限制： 树的结点度数没有限制；二叉树结点度数最大为 2。 有序性： 树的子树通常没有左右之分（除非是有序树）；二叉树严格区分左孩子和右孩 子，即使只有一棵子树也要区分左右。
2. ROM (Read-Only Memory) 与 RAM (Random-Access Memory)
(1) ROM (只读存储器)： 一种非易失性存储器。在正常工作状态下只能读出数据，不能（或 很难）写入数据。断电后数据不会丢失。常用于存放系统固件（BIOS）。
(2) RAM (随机存取存储器)： 一种易失性存储器。CPU 可以随时对任意地址进行读写操 作。断电后数据立即丢失。常用于存放运行中的程序和数据（主存）。
(3) 区别： 核心区别在于易失性（ROM掉电不失，RAM掉电丢失）和可写性（RAM可随意 读写，ROM通常只读）。
3. HTTP (HyperText Transfer Protocol) 与 FTP (File Transfer Protocol)
(1) HTTP (超文本传输协议)： 用于从 WWW 服务器传输超文本到本地浏览器的应用层协 议。它通常基于 TCP 连接，是无状态的，主要用于网页浏览。

1. 设 *A*, *B* 为两个相互独立的随机事件，已知 *P* (*A*) = 0.4, *P* (*B*) = 0.4, 则 *P* (*A* ∪ *B*)=()。 答案： 0.64 解析： 根据概率加法公式：*P* (*A* ∪ *B*) = *P* (*A*) + *P* (*B*) − *P* (*AB*)。 由于 *A*, *B* 相互独立，故 *P* (*AB*) = *P* (*A*)*P* (*B*) = 0.4 × 0.4 = 0.16。 所以，*P* (*A* ∪ *B*) = 0.4 + 0.4 − 0.16 = 0.64。
2. 假设一棵完全二叉树的高度为 *h* (根节点在第 1 层)，则该树的最少节点数为 ()，最多 节点数为 ()。 答案： 2

1. 已知 *A₁*,*A₂*, *A* 为三个随机事件，若事件 *A₁* 与 *A₂* 同时发生时，事件 *A* 必然发生，则 *P* (*A*) ≥ *P* (*A₁*) + *P* (*A₂*) − 1。 () 答案： T (正确) 解析： 题目条件意味着 *A₁* ∩ *A₂* ⊆ *A*，因此 *P* (*A*) ≥ *P* (*A₁* ∩ *A₂*)。 根据加法公式： *P* (*A₁* ∪ *A₂*) = *P* (*A₁*) + *P* (*A₂*) − *P* (*A₁* ∩ *A₂*)。 移项得： *P* (*A₁* ∩ *A₂*) = *P* (*A₁*) + *P* (*A₂*) − *P* (*A₁* ∪ *A₂*)。 因为 *P* (*A₁* ∪ *A₂*) ≤ 1，所以 *P* (*A₁* ∩ *A₂*) ≥ *P* (*A₁*) + *P* (*A₂*) − 1。 综上，*P* (*A*) ≥ *P* (*A₁*) + *P* (*A₂*) − 1。

1. 定义误区：将设计等同于“美化”或“造型”是工业设计早期的狭隘理解。
2. 现代设计内涵：现代设计（特别是“互联网+”背景下的设计）已经从单纯的“造物”演 变为 “解决问题” 的系统工程。它不仅包含视觉/形态设计（外观），还包含交互设计 （易用性）、服务设计（流程体验）、商业模式设计等。
3. 核心价值：设计的核心是 “以人为本”，即发现用户的痛点，并利用技术手段提供解决方 案，而外观只是解决方案的载体之一。例如，一个外观普通的 App 如果能高效解决挂号 难的问题，它依然是优秀的设计。

1. 技术基础：互联网思维确实是建立在互联网技术（连接、大数据、云计算）高度发展的基 础之上的。没有技术作为底层支撑，这种思维无法落地。
2. 本质界定：但严格来说，“互联网思维”本身不是技术，而是一种方法论和价值观。它是 指像互联网产品一样思考：如何低成本获取用户（免费思维）、如何快速响应变化（迭代 思维）、如何连接一切（平台思维）。
3. 结论：因此，更准确的说法是：互联网思维是基于互联网技术特征而演化出的一种全新的 商业与设计思维方式。不能将“思维”直接等同于“技术”。

### 四、 名词解释题（每题 6 分）

1. 循环链表 (Circular Linked List) 与 双向链表 (Doubly Linked List)
(1) 循环链表： 是一种首尾相接的链表。其特点是表中最后一个结点的指针域不为空，而是 指向头结点（或第一个结点），从而使整个链表形成一个环。由此可以从表中任一结点出发访

问到表中其他所有结点。

(2) 双向链表： 每个结点包含两个指针域，一个指向直接后继 (next)，另一个指向直接前驱 (prior)。其特点是能双向遍历，克服了单链表只能单向查找的缺点。
(3) 区别： 循环链表强调路径的闭合（环状），主要用于处理具有循环特性的数据（如约瑟夫 环）；双向链表强调访问的双向性，主要用于提高在已知结点附近插入、删除和查找前驱的效 率（以空间换时间）。
2. 计算机体系结构 (Computer Architecture) 定义： 指程序员所看到的计算机系统的属性，即计算机系统的概念性结构和功能特性。 内涵： 它主要研究软硬件功能的分配和界限，包括指令集结构 (ISA)、数据表示、寻址方 式、寄存器组织、中断机制等。 区别： 它不同于“计算机组成”(Organization)，后者关注具体的硬件实现（如数据通路宽 度、缓存策略）。体系结构决定了计算机“能做什么”，组成决定了“怎么做”。
3. 互动媒体 (Interactive Media) 与 游戏化思维 (Gamification)
(1) 互动媒体： 指利用数字技术，使用户能够通过输入（点击、触摸、语音等）主动参与内 容并获得即时反馈的媒体形式。其核心是双向传播和用户参与（如交互网页、VR 体验）。
(2) 游戏化思维： 是一种将游戏的设计元素（如点数、徽章、排行榜）和心理机制（如挑 战、竞争、成就感）应用于非游戏场景（如教育、管理、环保）的方法。
(3) 联系与区别： 互动媒体是技术载体或表现形式；游戏化思维是设计策略或方法论。互动 媒体不一定包含游戏机制（如 ATM 机），但游戏化思维通常需要依托互动媒体来实现。

### 四、 名词解释题

1. 数据结构 (Data Structure), 算法 (Algorithm), 程序 (Program) 数据结构：是指相互之间存在一种或多种特定关系的数据元素的集合。它包含逻辑结构、存 储结构和数据的运算三个方面。 算法：是对特定问题求解步骤的一种描述，是指令的有限序列。算法必须具备有穷性、确定 性、可行性、输入和输出五个特性。 程序：是用某种计算机语言编写的、能被计算机执行的代码序列。 辨析：数据结构是算法处理的对象，算法是处理数据结构的策略，而程序是数据结构和算法 在计算机上的具体实现（程序 = 数据结构 + 算法）。算法是抽象的，程序是具体的。

2. OSI 参考模型 (OSI Model), TCP/IP 模型 (TCP/IP Model) OSI 参考模型：即开放系统互连参考模型，由 ISO 制定，是一个7层的理论模型（物理层、 数据链路层、网络层、传输层、会话层、表示层、应用层）。 TCP/IP 模型：是互联网事实上的标准协议模型，通常分为4层（网络接口层、网际层、传输 层、应用层）。 辨析：OSI 模型学术性强，分层清晰，但实现复杂；TCP/IP 模型实用性强，是当前互联网的 基石。两者的主要区别在于层数划分和对会话/表示层的处理（TCP/IP 将其归并入应用层）。

### 四、 名词解释题（每题 6 分，共 18 分）

1. RAM (Random Access Memory), CPU (Central Processing Unit), GPU (Graphics Processing Unit)
(1) RAM (随机存取存储器)： 计算机的主存储器。具有易失性（断电数据丢失）和随机存取 （读写速度与位置无关）的特性，用于暂时存放 CPU 中的运算数据及与硬盘等外部存储器交 换的数据。
(2) CPU (中央处理器)： 计算机系统的运算和控制核心。主要由运算器 (ALU) 和控制器 (CU) 组成，负责解释计算机指令以及处理计算机软件中的数据。
(3) GPU (图形处理器)： 专门用于处理图像和图形运算的微处理器。与 CPU 相比，GPU 拥 有大量的计算核心，擅长大规模并行计算，如今广泛应用于游戏渲染、深度学习和科学计 算。
2. 堆 (Heap), 堆排序 (Heap Sort)
(1) 堆： 是一种特殊的完全二叉树结构。满足所有父节点的值都大于等于（或小于等于）其 子节点的值。前者称为大顶堆，后者称为小顶堆。它通常用数组来实现。
(2) 堆排序： 是一种基于堆结构的选择排序算法。其基本思想是将待排序序列构造成一个大 顶堆，此时整个序列的最大值就是堆顶的根节点。将其与末尾元素交换，然后将剩余 *n* − 1 个元素重新调整为堆，如此反复。其时间复杂度稳定为 *O*(*n*log*n*)，空间复杂度为 *O*(1)。
3. 非物质设计 (Immaterial Design), 网站转化率 (Website Conversion Rate)
(1) 非物质设计： 随着信息社会的发展，设计对象从有形的“物”转向了无形的 “服务”、 “体验”、“流程”和“数据”。它强调以非物质的形式满足人的需求，如交互设计、服务设 计。其核心在于“去物质化”和关注“使用权”而非“所有权”。
(2) 网站转化率： 是衡量网站运营效果的核心商业指标。指完成特定目标行为（如购买商 品、注册账号、下载文件）的访客人数占网站总访问人数的比例。 公式：转化率 = (转化次数/总访问量) × 100%。
### 五、 辨析题（每题 6 分，共 12 分）

1. 辨析题：“以用户为中心的设计”就是满足用户的所有需求。这种说法对吗？为什么？ 判断： 这种说法是错误（片面） 的。 理由：
1. 需求辨析 (Needs vs Wants)： 用户口头表达的往往是表面的“想要”(Wants)，而非深 层的真实“需要”(Needs)。设计师需要透过现象看本质，而不是盲目满足表面诉求。

2. 可行性与限制： 设计受限于技术可行性、商业成本、法律道德以及产品定位。满足“所 有”需求会导致产品功能臃肿（Feature Creep），失去核心竞争力。
3. 用户冲突： 不同用户群体的需求可能是冲突的。设计需要进行取舍，服务于核心目标用 户。
4. 结论： UCD (User-Centered Design) 的核心是理解用户，而非讨好用户。
2. 辨析题：电子游戏的设计必须考虑“数值平衡”。这种说法对吗？为什么？ 判断： 这种说法是基本正确的（视游戏类型而定，但普遍适用）。 理由：
1. 公平性与竞技性： 对于竞技类游戏（如 MOBA, FPS），数值平衡是游戏存在的基石。如 果角色或武器强弱失衡，会导致玩家流失，破坏游戏生态。
2. 心流体验 (Flow)： 对于单机或 PVE 游戏，数值平衡（难度曲线）决定了玩家的体验。 过难导致焦虑，过易导致无聊。良好的数值设计能让玩家保持在“心流”通道中。
3. 经济系统： 游戏内的经济数值平衡防止了通货膨胀，保证了游戏寿命。
4. 例外： 纯叙事类或艺术类游戏可能弱化数值，但广义的“体验平衡”依然存在。

### 四、 名词解释题（每题 6 分，共 18 分）

1. HTTP 协议 (HyperText Transfer Protocol), HTTPS 协议 (HyperText Transfer Protocol Secure), 并简述二者的区别。
(1) HTTP (超文本传输协议)： 是用于从万维网服务器传输超文本到本地浏览器的应用层协 议。它以明文方式传输数据，无状态，简单快速，默认端口为 80。

(2) HTTPS (安全超文本传输协议)： 是 HTTP 的安全版。它在 HTTP 下加入 SSL/TLS 层， 通过加密传输和身份认证来保证网络安全，默认端口为 443。
(3) 二者区别： 安全性： HTTP 明文传输，易被窃听；HTTPS 加密传输，安全性高。 端口： HTTP 使用 80 端口；HTTPS 使用 443 端口。 资源消耗： HTTPS 需要握手和加密解密，比 HTTP 消耗更多 CPU 和网络资源。
2. 生成树 (Spanning Tree), 最小生成树 (Minimum Spanning Tree)
(1) 生成树： 对于一个连通图，生成树是包含图中所有顶点（*n*个）的一个极小连通子图。它 含有 *n* − 1 条边，且没有回路。
(2) 最小生成树 (MST)： 在一个带权的连通无向图中，所有生成树中边权之和最小的那棵生 成树。
(3) 区别： 生成树关注的是连通性和边的数量（最少边）；最小生成树关注的是权值之和的最 小化（最小代价），通常用于解决网络布线、修路等成本优化问题。
3. 通用设计 (Universal Design), 用户留存率 (User Retention Rate)
(1) 通用设计： 指无需进行改良或特别设计，就能为尽可能多的用户（无论其年龄、能力或 状况）所使用的产品、环境或服务的设计理念。核心体现了设计的包容性与公平性。
(2) 用户留存率： 是互联网产品运营的核心指标，指在某段时间内，新增用户中经过一段时 间后仍继续使用产品的用户比例。它反映了产品的用户粘性和生命周期。
(3) 区别： 通用设计是设计方法论，关注产品的使用门槛和覆盖面；用户留存率是商业数据 指标，关注产品的运营效果和商业价值。

(1) 核心功能示意图 (20cm x 20cm 混合功能地图) (请在答题纸上绘制，布局参考如下) 标题： “清源卫士” (Eco-Guardian) —— 全民参与的 AI 污染防治监督平台。 左侧 (用户/痛点)： 市民： 发现黑臭水体/偷排烟雾，举报无门，流程繁琐，无反馈。 监管部门： 取证难，人力不足，响应慢。 中间 (核心界面)： 界面 A [AI 随手拍]： 相机取景框，实时识别污染类型（如“疑似水体富营养化”），自 动标注 GPS 和时间。 界面 B [污染热力图]： 地图上显示周边的污染举报点和治理进度（“已受理”、“治理 中”、“已复清”）。 右侧 (逻辑流)：
[市民拍照] → [CV 识别/LBS 定位] → [自动生成工单] → [区块链存证] → [执法部门接 单] → [反馈治理结果] 。 底部 (价值)： 精准治污 (AI 识别)。 依法治污 (链上存证)。 全民共治 (激励机制)。

(2) 设计说明 (300字以内) 设计方案：
#### “清源卫士”是一款连接公众监督与政府执法的污染防治协同 App。

目标用户与问题：

针对公众参与环保“取证难、反馈慢”的痛点，以及监管部门“发现难”的问题。

核心功能：

1. AI 智能取证： 引入计算机视觉技术，用户只需拍照，系统自动识别污染源类型（烟尘、固 废、水污）并进行初筛，结合 LBS 自动生成标准化举报工单，降低专业门槛。
2. 区块链全流程追踪： 举报数据上链存证，不可篡改。用户可像查快递一样实时追踪“受理-执 法-结案”全过程，确保“依法治污”的透明度。
3. 网格化热力图： 基于大数据的“污染热力图”辅助政府实现“精准治污”，优先处理高频举 报区域。
价值：

通过技术赋能，将分散的公众监督转化为精准的治理效能，构建“共建共治共享”的环保新格 局。
