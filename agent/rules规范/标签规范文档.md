# 🏷️ 标签与属性规范文档

> 本知识库的统一标签和属性管理规范，所有笔记必须遵循

---

## 📋 设计原则

| 原则 | 说明 |
|------|------|
| **中英结合** | 标签格式为 `#英文中文`，如 `#note笔记` |
| **双向搜索** | 搜英文前缀或中文都能找到 |
| **职责分离** | 标签管分类，属性管状态 |
| **简洁统一** | 避免冗余和混乱 |

---

## 💡 设计决策记录

### 为什么选择 `#英文中文` 格式？

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| `#note/设计理论` | 层级清晰 | 搜 `#设计理论` 找不到 | ❌ 不采用 |
| 双标签 `[note, 笔记]` | 中英文都能搜 | 每个笔记多一个标签 | ❌ 不采用 |
| `#note笔记` | 搜 `#note` 或 `#笔记` 都能找到 | 标签较长 | ✅ 采用 |

**最终结论**：采用 `#英文中文` 格式，一个标签同时支持中英文搜索。

### 为什么按考试科目分类？

笔记目录最初按知识领域分类（Math数学、DS数据结构等），但与考研科目结构不匹配。

**考研科目结构**：
- 政治（100分）
- 英语一（100分）
- 数学二（150分）
- 843专业课（150分）

**最终结论**：按考试科目分为四级（政治、英语、数学、专业课），专业课再细分为数据结构、计算机硬件、网络技术、设计理论、设计实践。

## 📊 属性规范

### 状态属性（status）

| 属性值 | 说明 | 适用场景 |
|--------|------|----------|
| `进行中` | 正在学习 | 新建笔记默认状态 |
| `待复习` | 需要复习 | 学完但未完全掌握 |
| `待回顾` | 定期回顾 | 已掌握但需定期复习 |
| `已掌握` | 完全掌握 | 可以不用再看 |
| `已归档` | 归档保存 | 不再关注 |

**状态流转**：
```
学习笔记：进行中 → 待复习 → 已掌握
错题记录：待复习 → 已掌握
知识卡片：进行中 → 待复习 → 待回顾 → 已掌握
```

### 优先级属性（priority）

| 属性值 | 说明 | 适用场景 |
|--------|------|----------|
| `高` | 高优先级 | 重点内容、高频考点、薄弱环节 |
| `中` | 中优先级 | 一般内容、常规知识点 |
| `低` | 低优先级 | 拓展内容、低频考点 |

### 来源属性（source）

| 属性值 | 说明 | 适用场景 |

## ⚠️ 使用规范

### ✅ 正确用法

```yaml
tags:
  - note笔记          # 类型标签（英文+中文）
  - theory设计理论    # 科目标签（英文+中文）
  - important重点     # 可选标记

status: 进行中         # 属性
priority: 高           # 属性
type: 笔记             # 属性
subject: 设计理论      # 属性
```

### ❌ 错误用法

```yaml
tags:
  - #note笔记          # 错误：不带 # 号
  - note/笔记          # 错误：不用斜杠分隔
  - note               # 错误：缺少中文
  - 笔记               # 错误：缺少英文
```

### 📌 注意事项

1. **标签格式**：`#英文中文`，直接连接，无分隔符
2. **Frontmatter 中不带 #**：写 `note笔记`，不是 `#note笔记`
3. **正文中带 #**：写 `#note笔记`
4. **每个笔记**：必须有一个类型标签 + 一个科目标签
5. **属性必填**：`status`、`type`、`subject`、`created`
