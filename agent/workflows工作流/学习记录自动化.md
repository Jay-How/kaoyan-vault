## 强制执行规则

### 规则 1：提交前必须审阅

以 [[agent/rules规范/Git规范|Git规范]] 为最高约束：

> 每次 Git 提交前，必须将提交信息提交给用户审阅，确认后再执行 commit！

自动化的边界止于**准备提交信息草稿**，不含执行 commit。展示草稿后等待用户确认。

### 规则 2：不补做以前没完成的任务

没做完的任务不顺延、不累积、不补做。自动化**不得**把以前没完成的任务搬进新记录。

### 规则 3：AI 生成内容打标签

新增或大改的记录须带 `AI-generated人工智能生成`。

### 规则 4：不臆造数据

用户未提供执行情况时，留空或标注待补，不得推测填写学习时长与完成度。

## 触发场景

### 场景 1：日常学习完成

**触发语句**：今天学了 XX、完成了 XX、XX 做完了

1. 更新当日记录的执行记录与学习时长
2. 按需创建笔记或错题
3. 准备提交信息草稿并等待确认

### 场景 2：日复盘

**触发语句**：复盘、今天结束了、收工

1. 填写当日记录的今日复盘（学习时长、完成任务、最大收获、遇到问题、明日调整）
2. 未完成项按规则 2 直接作废，不顺延
3. 准备提交信息草稿并等待确认

### 场景 3：每周复盘

**触发语句**：这周学完了、本周结束、周总结

1. 先跑日历（前置）：

   ```bash
   cd agent/tools工具
   ./读取日历.sh upcoming 14   # 下周课程、假期、补课
   ./读取日历.sh free          # 每周空闲时段
   ```

2. 填写周记录的学习统计与状态感受
3. 用真实课表核对「日程协同与时段分配策略」表，替代手工抄写
4. 规划下周：**按空闲时段分配**，课多的一周调低、课少的一周调高
5. 准备提交信息草稿并等待确认

> 日历依赖 DSH 的 `danger-full-access` 策略；`workspace-write` 下会被沙箱拦截。

### 场景 4：月度复盘

**触发语句**：这个月结束了、月度总结

1. 先跑 `./读取日历.sh timetable`，核算下月课业负担
2. 填写月度记录的复盘、关键过程指标与学习时长统计
3. 排下月计划，并把课业负担写入「课业负担与空闲时段」一节
4. 准备提交信息草稿并等待确认

### 场景 5：阶段性完成

**触发语句**：XX 阶段完成了、XX 一轮结束

1. 更新对应笔记的 `status` 属性
2. 在当日记录中记录里程碑
3. 按需更新 `01-Records记录/考研计划总览.md` 的里程碑表
4. 准备提交信息草稿并等待确认

## 状态定义

| status | 适用 |
| --- | --- |
| 进行中 | 当日/当周/当月尚未收口 |
| 已完成 | 记录类已收口 |
| 已归档 | 已复盘并入档 |

笔记的 status 取值与流转见 [[agent/rules规范/标签规范文档|标签规范]]。

## 执行规范

### 提交信息

格式与 type / scope 取值见 [[agent/rules规范/Git规范|Git规范]]。

### 文件更新顺序

1. 日历核对（按需）
2. 当日 / 当周 / 当月记录
3. 关联笔记与错题
4. 准备提交信息并**等待用户确认**
5. 用户确认后执行 commit
