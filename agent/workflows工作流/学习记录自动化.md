# 🤖 学习记录自动化工作流

> 本工作流定义了考研备考过程中的自动化规则，减少重复性操作

---

## 📋 工作流概述

### 目标

将以下手动流程自动化：
```
完成任务 → 更新Kanban → 更新每日记录 → Git commit
```

### 自动化后流程

```
用户报告完成情况 → AI自动执行所有更新
```

---

## 🎯 触发条件与执行规则

### 场景1：日常学习完成

**触发语句**：
- "今天学了XX，X小时"
- "完成了XX"
- "XX做完了"

**自动执行**：
1. 更新Kanban看板：移动任务到"Done已完成"列
2. 更新每日记录：填写执行情况、学习时长
3. Git commit：提交所有改动

**示例**：
```
用户：今天学了数学极限部分，完成了2小时
AI：
  1. 更新Kanban：将"高等数学极限习题"移到"Done已完成"
  2. 更新每日记录：填写学习时长2小时，记录完成内容
  3. Git commit：docs(records): 更新每日记录，完成数学极限部分
```

---

### 场景2：阶段性完成

**触发语句**：
- "XX阶段完成了"
- "XX基础打好了"
- "XX一轮复习结束"

**自动执行**：
1. 更新Kanban看板：归档已完成任务，添加新阶段任务
2. 更新每日记录：记录里程碑
3. 更新年度计划：标记完成进度
4. Git commit

**示例**：
```
用户：数学基础阶段完成了
AI：
  1. Kanban：归档基础阶段任务，添加强化阶段任务
  2. 每日记录：记录里程碑"数学基础阶段完成"
  3. 年度计划：更新数学进度为"基础完成"
  4. Git commit：docs(plan): 数学基础阶段完成，进入强化阶段
```

---

### 场景3：每周复盘

**触发语句**：
- "这周学完了"
- "本周结束"
- "周总结"

**自动执行**：
1. 生成每周总结（学习时长、完成任务、收获、问题）
2. 更新Kanban：规划下周任务
3. 更新每周目标看板
4. Git commit

**示例**：
```
用户：这周学完了
AI：
  1. 生成周报：统计本周学习时长、完成任务数
  2. Kanban：清理已完成任务，添加下周任务
  3. 每周目标：更新下周目标
  4. Git commit：docs(records): 本周学习总结，规划下周任务
```

---

### 场景4：添加任务

**触发语句**：
- "加个任务：XX"
- "新任务：XX"
- "待办：XX"

**自动执行**：
1. 更新Kanban看板：在"Plan计划"或"ToDo待办"列添加任务
2. 确认添加成功

**示例**：
```
用户：加个任务：概率论基础
AI：
  1. Kanban：在"Plan计划"列添加"概率论基础"
  2. 回复：已添加任务"概率论基础"到Plan计划
```

---

### 场景5：开始学习

**触发语句**：
- "开始学XX"
- "今天学XX"
- "做XX"

**自动执行**：
1. 更新Kanban：移动任务到"Doing进行中"列
2. 更新每日记录：记录开始学习的科目

**示例**：
```
用户：开始学数据结构
AI：
  1. Kanban：将"数据结构栈和队列"移到"Doing进行中"
  2. 每日记录：记录"14:00 开始学习数据结构"
```

## 📊 状态定义

### Kanban列状态

| 列名 | 含义 | 触发条件 |
|------|------|----------|
| Plan计划 | 长期目标，无截止日期 | 添加长期任务时 |
| ToDo待办 | 有截止日期的任务 | 确定截止日期时 |
| Doing进行中 | 正在做的任务 | 开始学习时 |
| Done已完成 | 完成的任务 | 完成任务时 |

### 每日记录字段

| 字段 | 内容 |
|------|------|
| 今日计划 | 当天要完成的任务 |
| 执行记录 | 实际完成的工作 |
| 学习时长 | 各科目学习时间 |
| 今日复盘 | 收获、问题、改进 |

## 🔧 执行规范

### Git Commit规范

```
<type>(<scope>): <subject>

类型：
- docs: 文档更新
- feat: 新增功能
- fix: 修复问题
- refactor: 重构
- chore: 杂项

范围：
- records: 记录相关
- plan: 计划相关
- kanban: 看板相关
- resources: 资源相关
```

### 文件更新顺序

1. **Kanban看板** → `01-Records记录/考研Kanban系统.md`
2. **每日记录** → `01-Records记录/Daily每日/YYYY-MM-DD Weekday.md`
3. **年度计划** → `01-Records记录/Yearly年度/` （按需更新）
4. **Git commit** → 提交所有改动

## 📝 使用示例

### 完整工作流示例

```
用户：今天学了高等数学极限，2小时，做完了习题

AI自动执行：
1. 更新Kanban：
   - 将"高等数学极限习题"从"ToDo待办"移到"Done已完成"

2. 更新每日记录：
   - 执行记录：完成高等数学极限习题
   - 学习时长：数学2小时
   - 执行情况：已完成

3. Git commit：
   docs(records): 完成高等数学极限习题
   
   主要修改：
   - 更新Kanban：移动任务到已完成
   - 更新每日记录：记录学习2小时

4. 回复用户：
   ✅ 已更新！
   - Kanban：高等数学极限习题 → Done已完成
   - 每日记录：已记录2小时学习
   - Git commit：已提交
```

## ⚠️ 注意事项

1. **确认后再执行**：重要操作前先询问用户确认
2. **保留备份**：重大修改前先备份
3. **格式规范**：遵循项目的标签和属性规范
4. **及时提交**：每天结束时确保所有改动已提交
