## 📋 标签系统设计（2025-08-20）

### 决策：选择 `#英文中文` 格式

**问题**：如何让搜 `#note` 和 `#笔记` 都能找到笔记？

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| `#note/设计理论` | 层级清晰 | 搜 `#设计理论` 找不到 | ❌ |
| 双标签 `[note, 笔记]` | 中英文都能搜 | 每个笔记多一个标签 | ❌ |
| `#note笔记` | 搜 `#note` 或 `#笔记` 都能找到 | 标签较长 | ✅ |

**结论**：采用 `#英文中文` 格式，一个标签同时支持中英文搜索。

## 🔌 Periodic Notes 配置失败（2025-08-20）

### 问题

Periodic Notes 创建文件时模板没有自动填充，Templater 语法 `<% tp.date.now() %>` 原样保留。

### 原因

- Periodic Notes 使用 Obsidian 原生语法 `{{date:xxx}}`
- Templater 语法不被 Periodic Notes 识别

### 解决

- 创建 `Templates/periodic-notes/` 文件夹
- 使用原生语法创建专用模板
- Templater 模板保留给手动插入使用

### 教训

不同插件使用不同的模板语法，需要分别处理。

## 🏗️ agent.md 重构设计（2025-08-21）

### 决策：高内聚、低耦合

**问题**：agent.md 承担了太多职责（索引、规范、速查、查询等），362 行，AI 阅读成本高。

**原则**：
- agent.md 只做窗口：项目概览、目录结构、索引链接
- 详细内容放在 agent/ 子文件夹
- 每个文档只负责一个主题

**结论**：
- agent.md 精简到 155 行
- 规范类放 `rules规范/`
- 参考类放 `ref参考/`
- 插件指南放 `plugins-guide/`

## 📐 新增内容规范（2025-08-21）

### 原则

给 Agent 提供新的工作流或信息时，必须遵循高内聚、低耦合原则。

### 步骤

```
1. 确定内容类型（规范/参考/工作流）
   ↓
2. 在 agent/ 对应文件夹创建新文档
   ↓
3. 在 agent.md 中添加索引入口
   ↓
4. 更新相关交叉引用
```

### 文件夹归属

| 内容类型 | 存放位置 | 示例 |
|----------|----------|------|
| 规范类（必须遵循） | `agent/rules规范/` | Git规范、变更管理 |
| 参考类（快速查阅） | `agent/ref参考/` | 标签速查、模板清单 |
| 工作流类 | `agent/ref参考/` | 学习工作流 |
| 经验教训类 | `agent/ref参考/` | 本文档 |
| 插件指南 | `agent/plugins-guide/` | 各插件使用说明 |
| 核心规范 | `agent/rules规范/` | 标签规范文档 |

## 🚫 错误示例

### 错误：把经验教训塞到规范文档

**做法**：在变更管理规范中添加实战案例

**问题**：
- 增加规范文档长度
- 增加 AI 阅读成本
- 违反高内聚原则

**正确做法**：创建独立的经验教训文档，规范文档只保留规则。
